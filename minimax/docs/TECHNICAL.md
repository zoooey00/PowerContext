# 一页技术说明

作品名称：规有所依——面向软件持续演进的 SDD 上下文管理系统。

模块结构：CLI (`sdd/__main__.py`) → 工程导入及来源校验 (`sdd/core.py`) → seekdb 工程索引 → 上下文 JSON → MiniMax HTTP 代码修改 → 不变目标/回归测试 → PowerContext HTTP 状态写入 → 新进程状态召回与后续上下文。

工程索引：规格按条目导入，代码与测试按文件导入并提取 AST 符号。保存 path、symbol、kind、content、revision、tags、SHA-256。导入在事务中整体替换索引，删除与修改的规格不会残留。根据任务词项参数化查询，结果原文用于构造实际模型请求。构造前校验必要来源与当前磁盘哈希，防止过期索引。

MiniMax 分工：接收本次任务、数据库命中来源和历史验证，生成完整 business/tickets.py；只应用到该文件，测试保持不变。记录请求、模型名、请求 ID、usage、最终回答、补丁与生成代码哈希；不保存私有推理。独立验证前后行为，拒绝缺失函数或不完整响应。

seekdb/OceanBase 分工：实际保存工程资料和检索。采用 MySQL 协议与 PyMySQL；小样例使用可解释词项检索，避免嵌入模型依赖。数据库查询审计记录 SQL、参数、命中 ID；数据库版本由运行记录提供。

PowerContext 分工：用固定提交的真实服务，通过 scopes 创建任务隔离边界，memory/remember 保存完成项、待办和验证结果，context/prepare 召回。每次 demo 新建任务标识验证空状态；新解释器重新连接服务器，将召回结果用于下一步上下文。历史内容标为资料，以当前源码和规格为准；不把它当执行指令。

验收证据：before/after 快照、不可变测试哈希、统一 diff、命令/退出码/代码哈希、DB 查询、模型请求与回答、状态写读、子进程恢复上下文与规格修订结果。没有用截图替代源码或验证。

边界：单项目串行使用；没有完整 Agent 框架、生产多租户控制和大型代码库向量索引。服务环境与凭据由复现者配置，交付不依赖本次临时云实例。
