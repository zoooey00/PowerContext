# 可重复验收样例

## A. 真实 Dify 三会话玩法（已执行）

初始条件：按 README 启动网关及 PowerContext，导入唯一 DSL、绑定有效模型、配置环境变量并发布。使用同一 Dify Web App 浏览器身份；新建存档名，例如 `judge-当天时间`，不能复用已经玩过的存档。无知识库或预置数据。

| 顺序 | 操作及输入 | 必须观察到的表现 |
| --- | --- | --- |
| 1 | 新建聊天，填存档名；发送 `恶作剧：会打嗝的月亮` | 召回为空；模型描述第一次恶作剧；收据第 1 回合，警惕 2/5、交换价 7；保存节点返回真实 Memory Artifact 引用 |
| 2 | 点击“开启新对话”，在“新对话设置 → 编辑”中填入并确认相同存档名；发送 `交换：一双失眠的拖鞋` | 召回里出现“会打嗝的月亮”；模型回扣月亮；收据第 2 回合，警惕 2、交换价 7 |
| 3 | 再新建聊天，编辑并确认相同存档名；发送 `道歉：一颗薄荷糖` | 召回里有月亮和拖鞋；模型接受赔礼；收据第 3 回合，警惕 1、交换价 5 |
| 4 | 新建聊天，改用全新存档名；发送 `看看：柜台` | 没有之前玩家经历；第 1 回合，警惕 0、交换价 3 |

第 2 步必须是独立 conversation_id，否则不能证明跨会话。模型措辞没有唯一答案，但不得把没有发生的细节当成记忆；规则以收据为准。如模型未引用召回物品，应保留失败记录检查提示与模型，不能把手写台词充当实际回复。

自动方式：`verify_dify.py` 每次生成新 end-user，确保空档，执行前三步并检查三个不同 conversation_id。该脚本需要已发布的 Chatflow API Key。成功才输出 `evidence/dify-live.json`。**本次已经执行通过；最终云端 DSL 重新导入并发布后再次执行了该脚本，最终结果已提交。**

匿名网页也独立执行了前三步，新对话时均重新确认同一存档名。实际界面见 `evidence/dify-web-1.png`、`dify-web-2.png`、`dify-web-3.png`，可见文本记录在 `dify-web-run.json`。网页结果与 API 结果是两组不同玩家的数据，不应混用其回合标识。

最终重新导入返回 `status=completed`，DSL 版本与服务端均为 0.7.0，warnings 为空，见 `evidence/dify-reimport.json`。真实预览的 9 个节点均 succeeded，包含 HTTP 写入及读回与 DeepSeek 返回，见 `dify-node-trace.json`。其来源是首次成功预览；最终重新发布版本的三会话结果另见 `dify-live.json`。

提交的证据覆盖：

1. Dify 重新导入成功响应与服务端声明的 DSL 版本（云端服务器源码版本不可固定）。
2. 实际供应商为官方 DeepSeek 0.0.26，型号 deepseek-flash，非思考模式；包标识固定在导出 DSL 中，不交付凭据。
3. 第 1 次召回空记录、第 1 次保存 HTTP 200 与返回引用。
4. 第 2 次召回中具体物品、送进 LLM 的 context、第 2 次回复及收据。
5. 第 3 次道歉后的价格为 5；三会话 API 与网页结果分别有记录。
6. [正式 Web App 入口](https://udify.app/chat/neneiRJSfXTqgv64) 的匿名浏览器体验。当前演示依赖作者本机和临时隧道在线，稳定部署或离线后重建方式见 README。

重置：每次更换角色存档名或 API end-user，无需手动修改数据库。旧数据保留，可供复查。

## B. 已执行的真实 PowerContext 后端验证

命令：`python verify.py`（在安装完成的虚拟环境中）。环境、时间、请求、实际写入返回、独立 Artifact 引用和召回正文保存在 `evidence/backend-run.json`；服务级读写日志在 `evidence/services.log`。

结果：空档 → 恶作剧后价格 7 → 重启 PowerContext 进程 → 召回月亮、价格仍 7 → 不同用户空档、价格 3 → 交易成功 → 拒绝旧票据 → 道歉后价格 5。另验证同一票据重复提交不会新增回合，以及无效 token 返回 401。

脚本使用固定“测试台词”，用于把记忆与规则验证从模型的随机输出中分离。**它没有导入 Dify、没有执行 LLM，不能代替样例 A 或作为完整验收已通过的证据。**

## C. 故障体验

停止网关后在 Dify 发送消息，应报 HTTP 连接失败，不输出“记忆已保存”。恢复网关后新发行动。模型服务不可用或 Key 无效时，应停在模型节点，不触发记忆写入。这些是可补充执行的故障检查方法，本次未专门中断已发布应用的网络或模型服务来取得故障证据；不要将其与已通过的正常三会话及后端异常检查混同。
